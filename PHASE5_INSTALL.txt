ProcureFlow | PHASE 5 — Automated Procurement Workflow Verification
=================================================================

BASELINE
- Built on the working ProcureFlow code with Phases 1–4 and the corrected
  Phase 3 SQL migration 0021 present in the working tree.
- The ZIP contains ONLY changed and newly added files.
- This phase adds isolated integration tests and automatic PR verification.
- No production Worker code, D1 tables, records, or user accounts are changed.
- No database migration or API Worker deployment is required for these files.

FILES
1) package.json
   Adds: npm run test:workflow
   Existing npm test automatically includes the Phase 5 test file.
2) tests/phase5HttpWorkflow.test.mjs
   15 HTTP integration tests against real Worker route handlers.
3) tests/helpers/localD1.mjs
   In-memory SQLite/D1 adapter. Applies src/db/schema.sql and all actual
   cloudflare/migrations/*.sql files in order. Creates disposable test accounts.
4) tests/helpers/workerRunner.mjs
   Transpiles production Worker TS handlers into a temporary directory so
   Node 22 can exercise them directly with Request/Response. Does NOT modify
   or mock the business logic; removes temporary files after tests.
5) .github/workflows/verify-pull-request.yml
   Automatically tests and type-checks pull requests against main and runs
   npm run build. Does not deploy, require API keys or use production D1.
6) PHASE5_INSTALL.txt
   This deployment and limitations guide.

INSTALLATION
- Extract the ZIP into your project ROOT, preserving directory names.
- Only added/changed files are included. Do not delete unrelated modules.
- Node.js 22 or newer is required for the built-in SQLite test harness.
- The new tests use the already-declared TypeScript dependency; they do not
  require Playwright, Miniflare or extra database dependencies.

In PowerShell, from your repository root:

  npm ci
  npm run test:workflow
  npm test
  npm run build

To type-check the Worker:

  cd cloudflare
  npm ci
  npx tsc --noEmit --skipLibCheck --target es2022 --module esnext --moduleResolution bundler --allowImportingTsExtensions --types @cloudflare/workers-types src/index.ts
  cd ..

- The new PR verification workflow starts on pull requests targeting main,
  and can also be manually triggered from GitHub Actions.
- Existing main-branch deployment workflow remains unchanged and continues
  running npm test before deploying your website.
- If your Node 22 prints an experimental node:sqlite warning, that warning
  alone is not a failed test. Check the test exit status.
- Phase 5 needs NO Wrangler deploy or D1 schema change.
